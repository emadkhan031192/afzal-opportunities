## 1. Push notifications — DECISION NEEDED (recommend Option A)

**Option A — no-cost background checks (recommended).** `workmanager`
periodic task (every 30–60 min, user-configurable) re-runs the app's
published-only Firestore query (same query as `AdvertisementService`),
compares against a stored "last seen" watermark in SharedPreferences, and
fires `flutter_local_notifications` for: (a) ads published since the last
check, (b) bookmarked/open ads whose deadline is ≤ 48h away (dedup by ad
id + day). Works on the current Firebase Spark plan — no billing change,
no server code. Honest limits: not instant (checks are periodic), and
aggressive battery optimization on some phones can delay checks.

**Option B — true instant push.** Requires the Blaze billing upgrade (the
same pending decision as Firebase Storage), plus `firebase_messaging` and
a Cloud Function that sends FCM on new/updated Firestore docs.

Recommendation: ship Option A in v1.3.0; revisit B only if/when Blaze is
approved. The plan below assumes A unless the user picks B.

New deps: `workmanager`, `flutter_local_notifications` (pin to versions
compatible with the CI Flutter SDK at build time; flutter_local_notifications
22.x needs Flutter ≥ 3.38 / AGP 8.11 / compileSdk 35 — verify during
implementation).

Build notes (2026-10-09, Flutter 3.35.6):
- `workmanager` is pinned to `^0.9.2` with a `dependency_overrides` pin of
  `workmanager_apple: 0.9.6`. The `workmanager_apple` 0.9.4 release does not
  implement the `foregroundServiceConfig` parameter added in
  `workmanager_platform_interface` 0.9.4, which fails the release Dart
  compile; 0.9.6 is the matching Apple implementation for the 0.9.x line.
  (0.9.3+/0.10.x need Flutter ≥ 3.47, newer than CI.)
- `android/app/build.gradle.kts` enables core library desugaring
  (`isCoreLibraryDesugaringEnabled = true` +
  `coreLibraryDesugaring("com.android.tools:desugar_jdk_libs:2.1.5")`)
  because `flutter_local_notifications` requires it.

## 2. Urgency-colored deadline headline badges

Mostly done already — this is assembly, not invention:
- `lib/core/utils/deadline.dart` already computes `DeadlineTone`
  (success/warning/danger/neutral) per ad in PKT.
- `lib/widgets/deadline_badge.dart` already maps tones → palettes
  (mint / amber / red tints, dark-mode aware).
- Work: promote the badge to the headline position on `job_list_card.dart`,
  `job_grid_card.dart`, `featured_card.dart` and `details_screen.dart`
  (full-width 40dp hero pill, `expanded: true`, already supported); add
  widget tests asserting tone→color mapping in both themes.

## 3. Urdu language option

No l10n infra exists today. Scope (~57 UI strings found in
`lib/screens` + `lib/widgets`, plus deadline labels):
- Add `flutter_localizations`, `lib/l10n/app_en.arb` + `app_ur.arb`,
  wire `localizationsDelegates` + `supportedLocales` in `app.dart`.
- `LocaleController` mirroring `ThemeController` (persist in
  SharedPreferences); language switcher next to the theme toggle.
- RTL comes free via `MaterialApp.locale` (Directionality flips).
- Ad content itself stays as published (Urdu/English per the admin) —
  only app chrome is translated. Deadline labels get Urdu equivalents
  (e.g. "آخری تاریخ آج").

## 4. Dark mode

Infra already exists: `ThemeController` (persisted), `AppTheme.lightTheme()`
/ `nightTheme()`, wired via `themeMode` in `app.dart`. What's missing:
- A visible toggle — none is wired in the UI today (the shell comment
  mentions one, but no `themeController.toggle()` call exists in any
  screen). Add it to the header/settings.
- QA pass: v1.2.0's pastel list/grid cards were designed light-first;
  verify contrast and adjust tints under the night theme.

# Release builds & signing — Afzal Opportunities

## 1. Create an upload keystore (once, keep it secret)

```bash
keytool -genkey -v \
  -keystore ~/afzal-upload-key.jks \
  -keyalg RSA -keysize 2048 -validity 10000 \
  -alias afzal
```

Back it up somewhere safe (password manager + offline copy). If it is lost,
you cannot update the Play Store listing under the same signing key.

> Never commit `*.jks`, `*.keystore` or `key.properties` — they are all
> git-ignored.

## 2. Create `android/key.properties` (git-ignored)

```properties
storePassword=<your store password>
keyPassword=<your key password>
keyAlias=afzal
storeFile=/absolute/path/to/afzal-upload-key.jks
```

## 3. Wire signing into the Android build

In `android/app/build.gradle.kts` (generated by `flutter create`), add
before the `android { }` block:

```kotlin
val keystoreProperties = java.util.Properties().apply {
    val f = rootProject.file("key.properties")
    if (f.exists()) load(java.io.FileInputStream(f))
}
```

and inside `android { }`:

```kotlin
signingConfigs {
    create("release") {
        keyAlias = keystoreProperties["keyAlias"] as String?
        keyPassword = keystoreProperties["keyPassword"] as String?
        storeFile = keystoreProperties["storeFile"]?.let { file(it as String) }
        storePassword = keystoreProperties["storePassword"] as String?
    }
}
buildTypes {
    getByName("release") {
        signingConfig = signingConfigs.getByName("release")
    }
}
```

## 4. Build

```bash
# Installable release APK (for direct distribution / testing)
flutter build apk --release
# -> build/app/outputs/flutter-apk/app-release.apk

# Android App Bundle (required for Google Play upload)
flutter build appbundle --release
# -> build/app/outputs/bundle/release/app-release.aab
```

## 5. Versioning

Bump `version:` in `pubspec.yaml` (`1.0.0+1` → `1.0.1+2`, …) for every
store release. The number after `+` is the Android `versionCode` and must
increase.

## 6. Google Play notes

- New apps must be uploaded as an **AAB**, not an APK.
- Complete the Play Console data-safety form: the app reads public ad data
  from Firestore and stores theme/bookmark preferences on-device only.
- The app targets the `made for everyone` audience; no account is required.
- Internal testing track first, then promote to production.

## 7. CI-built (unsigned) APKs

APKs built by GitHub Actions (`.github/workflows/android-apk.yml`) or
Codemagic (`docs/codemagic.md`) without your keystore are signed with a
debug key. They install and run fine for testing, but **cannot** be
uploaded to Google Play. Add your keystore as encrypted CI secrets to
produce a properly signed release (see the workflow file comments).
